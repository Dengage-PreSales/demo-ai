eComm Demo Factory

Reading the sandbox configuration.

1. Fire a scenario

Each card pushes its event to window.dataLayer and records the click to sandbox_onsite_events. A widget appears only if a campaign exists in the panel with that exact trigger name. If one is missing, that card is silently dark: nothing errors and nothing logs, so check the campaign list before suspecting the code.

2. Record a storefront event

The second table, written the way the storefront will write it. This is a fixed set of events sending a fixed set of columns. There is no field here for choosing a table, and that is deliberate: the two sandbox tables are the only ones any part of this repository may write to.

3. Web push

Push subscriptions belong to the origin, and every demo shares one origin. A browser that subscribes here is subscribed for the whole sandbox. For composing a push in the panel during a call and having it arrive on screen, that is the behaviour you want. Handoff 2.5.

4. Reset the widget display state

A campaign has a display frequency, and the SDK also keeps display state in this browser. Fire the same widget twice on a call and the second one may not appear, which looks like a broken product. Clearing that state is the fix, not rebuilding the campaign. Handoff 2.6.
